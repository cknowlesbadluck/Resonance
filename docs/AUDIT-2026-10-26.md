### `githubAdapterConfigured: false`: expected, not a gap

- `src/deploy/contract.ts` lists `GITHUB_TOKEN` as `requiredInProduction: false` (role `adapter`).
- `src/deploy/advisory.ts` classifies its absence as an *advisory* gap: "GitHub adapter is optional. Absence is not a ready blocker."
- `src/nexus/runtime.ts` only registers the GitHub adapter and the `github.repository.read` capability when the token is set.

Effect: Nexus can't read GitHub repositories in prod. That is a feature choice, and it is owner-only because it needs a secret. Not a readiness or safety problem.

## Addendum 2026-10-26 06:00 ET: capability, chamber and adapter planes

**Resonance (V = read from code at e01421d):**
- **Chambers are planned, not implemented.** `src/chambers/runtime.ts` and `nexus.ts` are interfaces and types only (V).
- **The policy gate is dead code with a fail-open trap.** `DefaultPolicyGate` in `src/policy/gate.ts` has no caller anywhere (V, grep). Privileged and unknown levels return `allowed: true, requiresApproval: true`, while `requirePolicy()` only throws when `!allowed`. A caller that relies on `requirePolicy` alone would run privileged actions without approval. `read` and `analyze` pass for any non-empty actor and project with no grant lookup. **Proposal (two-key, not implemented):** `requirePolicy` throws on `requiresApproval` unless an approval token is passed; add a deny-by-default test; wire it before any chamber ships.
- **Provider adapters (`lib/ai`).** Imported nowhere outside `lib/ai` (V), so the "provider-neutral Nexus" is not live yet. Adapters fail closed when the key is missing (V, now tested). Gemini sent the API key in the URL query (V); that is fixed in #242, which also adds the adapter contract test. The orchestrator records `error` strings, so key-free errors matter.
- **Routes.** 10 of the 11 `app/api` routes use the auth helper. `webhooks/github` authenticates by HMAC signature (`decideGitHubWebhook`) and refuses without persistence (V). The remaining gap is ordering: some routes validate before they authenticate (400 before 401). #243, #244 and #246 fix it.
- **Logging and PII.** `console.error` in the webhook and resume routes logs the raw Supabase error object, which can carry row details. That needs a small sanitize step (propose: reuse the `persistenceErrorResponse` path from #172).

**Conduit (V at d44b971):** 35 MCP tools in `src/tool-surface.snapshot.json`. `src/tool-gates.test.ts` invokes every tool with no scopes and requires a refusal (deny-by-default, behavioural), and the `PUBLIC_TO_AUTHENTICATED` allowlist is empty. Logs in `src/mcp.ts` redact paths and errors but record the actor subject (a pseudonymous id). No tool-surface gap found.

**Deployment readiness:** both owned planes are ready (V). Resonance `githubAdapterConfigured: false` is advisory. Neither app is ready for capability execution in production until phase 9.
